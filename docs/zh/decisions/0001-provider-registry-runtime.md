# 0001：提供者、注册中心、运行时

## 状态

已采纳。

## 背景

原始的工具系统混合了静态工具定义、handler 查找和运行时调用。对于少量内置工具来说这是可行的，但它没有为 MCP 留下干净的路径——在 MCP 中，工具是动态发现的，且提供者可以独立失败。

我们需要一个模型，既能支持内置工具，又能支持外部提供者，而不需要让 agent 循环了解每种来源类型。

## 决策

使用三个层次：

- 提供者：从一个来源加载工具并返回 `RegisteredTool[]` 及诊断信息。
- 注册中心：存储已注册的工具和提供者诊断信息。
- 运行时：通过注册中心调用工具。

agent 循环只接收工具定义并调用运行时调用。

## 后果

好的方面：

- 工具来源的差异保持在循环之外。
- MCP 可以作为另一个提供者添加。
- 注册中心可以在不注册损坏工具的情况下解释不可用的命名空间。
- 运行时不再需要自己的 handler 映射。

权衡：

- 启动组装更加显式。
- 测试需要在更多地方构建 registry/runtime。

## 不变量

- `RegisteredTool.name` 必须等于 `definition.name`。
- 重复的工具名称会导致注册失败。
- 提供者诊断信息不得包含秘密。
- 循环不得导入提供者。
