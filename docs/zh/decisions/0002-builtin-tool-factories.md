3|# 0002：内置工具工厂
4|
5|## 状态
6|
7|已采纳。
8|
9|## 背景
10|
11|在引入 `RegisteredTool` 之后，内置工具仍然驻留在一个集中的 `toolHandlers.ts` 文件中。这在一个地方保留了过多的所有权，并使内置提供者感觉像一个重新命名的全局 handler 表。
12|
13|期望的所有权模型是每个工具拥有自己的定义和 handler。
14|
15|## 决策
16|
17|将内置工具移到 `src/tools/builtin/**` 下。
18|
19|每个工具文件导出一个工厂：
20|
21|```ts
22|createXTool(deps): RegisteredTool
23|```
24|
25|组索引聚合相关工具。内置提供者加载顶层的内置索引并返回生成的工具。
26|
27|## 后果
28|
29|好的方面：
30|
31|- 工具的所有者一目了然。
32|- 定义和 handler 不会在分散的文件中漂移。
33|- 新工具遵循可重复的路径。
34|- 内置工具和未来的 MCP 工具共享相同的最终形态。
35|
36|权衡：
37|
38|- 文件更多。
39|- 简单工具有稍微多一些样板代码。
40|
41|## 不变量
42|
43|- 不要重建 `src/tools/toolDefinitions.ts`。
44|- 不要重建 `src/tools/toolHandlers.ts`。
45|- 组索引仅做聚合。
46|- 保持内置工具顺序显式。
